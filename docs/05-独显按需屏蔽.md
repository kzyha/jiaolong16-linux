# 独显按需屏蔽方案（含翻车与恢复全记录）

## 方案 v2（当前部署）

```
开机(dgpu-off.service, Before=greetd.service)
  └─ 物理摘除独显 01:00.0 → 0W
插件功耗轮询(3s)
  ├─ 检测 ADP1 在线 + 独显未开 → 自动 gpu on
  └─ 检测拔电(策略开) → gpu rtd3 (设备保留, RTD3省电, 零死锁)
手动: gpu on 随时可用; gpu off 带占用保护
```

部署物：
- `/etc/modules-load.d/mhwd-gpu.conf` 注释掉 nvidia 行（**关键**——modules-load.d 是显式点名加载，modprobe blacklist 拦不住）
- `/etc/modprobe.d/nvidia-off.conf` 黑名单（拦 udev 别名加载）
- `dgpu-off.service`：`WantedBy=graphical.target` + `Before=greetd.service`（时序！）
- `dgpu-uninstall` 一键回滚 + mhwd-gpu.conf 备份 + snapper 快照

## v1 翻车复盘（为什么必须读）

v1 三个叠加错误导致**开机黑屏，靠 snapper 快照救回**：

1. **黑名单无效**：Manjaro 的 mhwd-gpu.conf 显式加载 nvidia，blacklist 形同虚设
2. **时序竞争**：服务挂 multi-user.target 与 greetd 并行——niri 已把 NVIDIA(card0) 选为主 GPU，服务随后拔设备
3. **niri 无回退**：主 GPU 消失后无限重试 `error creating renderer for primary GPU: NoDevice`，不会切核显

日志铁证：`NVRM: Attempting to remove device 0000:01:00.0 with non-zero usage count!`

**恢复路径**（存档备用）：GRUB 选 snapper 快照进只读系统 → `mount -o subvol=@ /dev/nvme0n1p2 /tmp/realroot` → 删除肇事文件 → 重启回真实子卷。

## 深层内核结论（实测）

| 操作 | 结果 |
|------|------|
| 无占用时 PCI 摘除 | ✅ 干净，0W |
| 被持有(niri 等)时热拔 | ❌ **内核死锁**（D 状态，永远完不成；辅助位也不行） |
| 半死设备的 gpu on | ❌ modprobe 挂起（跟摘除一半的设备对话无回应） |
| 中毒会话的关机 | ❌ niri 退出时清理僵死 GL 上下文超时 → SIGKILL 链仍卡 → 需断电冷启 |
| 被持有时的 RTD3 | ✅ ~9.2W P8（物理下限，niri 的 EGL 上下文阻止深度睡眠） |

**独显状态机一旦异常，唯一恢复手段 = 断电冷启动。** 所有写操作必须带占用保护。

## 其他

- HDMI 音频功能块 01:00.1 运行时 unbind 同样会死锁（GPU 核心摘除后 HDA 无法下电），本次放弃处理（耗电极小）
- niri 是 smithay 框架：不认 `WLR_DRM_DEVICES`，且固定枚举打开所有 GPU（热插入即抓取）——用户态无法阻止
- CPU 功耗：`/sys/class/powercap/intel-rapl:0/energy_uj` Δ 读 + 计数器回绕处理（AMD 平台同样走此接口）
